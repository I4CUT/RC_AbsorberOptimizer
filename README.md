# RC Absorber Optimiser

(c) Разработано в лаборатории элионики НИИПФП им.А.Н. Севченко БГУ "Парфимович И.Д., Комаров Ф.Ф., Пилько В.В. (мл.), Капура И.В., Чижов И.В."

Многослойный оптимизатор радиопоглощающих покрытий (РПП) на основе метода
матриц передачи (TMM), NSGA-II и Differential Evolution (DE), с локальной
базой данных истории вычислений и опциональным ML-ускорением поиска
(forward-суррогат + seed-proposer).

## Возможности

- **Честный физический расчёт** отражения многослойного покрытия
  (воздух → слои → металл) методом TMM.
- **Двухуровневая оптимизация**: NSGA-II подбирает последовательности
  материалов, Differential Evolution — толщины слоёв для каждой
  последовательности.
- **Inverse Design** — задаёте целевую полосу частот, порог RC и максимальную
  толщину, а не оптимизируете по всему измеренному диапазону материалов.
- **Локальная база данных (SQLite)** — все материалы, прогоны и найденные
  покрытия накапливаются автоматически, с дедупликацией и историей.
- **ML-суррогат** — модель, предсказывающая кривую RC(f) по составу
  покрытия, обучается на накопленных данных и ускоряет поиск.
- **Seed-proposer** — суррогат предварительно ранжирует последовательности
  материалов перед тем, как честный DE+TMM проверяет только лучшие из них.
- **Экспорт датасета** одним кликом — из БД в формат, готовый для обучения
  ML-моделей (CSV + NumPy-тензоры).

Ключевой принцип, пронизывающий весь проект: **что бы ни использовалось для
поиска (суррогат, seed-proposer), итоговые результаты, которые попадают в
базу данных и которые видит пользователь, всегда честно перепроверяются
настоящим TMM-расчётом.** Суррогат не может исказить сохранённые данные —
только повлиять на скорость и качество поиска.

## Запуск

```bash
pip install numpy scipy pandas matplotlib openpyxl scikit-learn joblib
python main.py
```

`scikit-learn`/`joblib` нужны только для вкладки «Нейросеть (суррогат)» —
без них честный TMM-режим работает как обычно, вкладка ML-суррогата в окне
БД покажет сообщение об отсутствующих зависимостях вместо падения всего
приложения.

## Входные данные

Папка с `.xlsx`-файлами, один файл = один материал. Обязательные столбцы:

| Столбец | Описание |
|---|---|
| `f` | Частота, Гц |
| `er` / `eim` | Re/Im относительной диэлектрической проницаемости εr |
| `mr` / `mim` | Re/Im относительной магнитной проницаемости μr |

Частотные сетки всех материалов одного прогона должны совпадать.

## Режимы работы

Главное окно разделено на две вкладки метода расчёта:

### 1. TMM + NSGA-II + DE (честный расчёт)

Обычный режим. Задаются: папка материалов, режим оптимизации (лучший RC /
тонкий / компромисс), максимальное число слоёв, порог RC, максимальная
толщина покрытия (через множитель длины волны λ на центральной частоте).

Дополнительно можно включить **Inverse Design** — чекбокс «Целевая полоса
частот» в той же группе. При включении:
- вместо множителя λ задаётся полоса частот (ГГц) и максимальная толщина
  напрямую (мм);
- поиск фокусируется именно на этой полосе (быстрее полного диапазона);
- порог RC применяется как целевой уровень внутри полосы;
- честная TMM-проверка в конце всё равно считается по всему измеренному
  диапазону материалов — сохранённая кривая показывает полный спектр,
  а метрики валидности относятся именно к целевой полосе.

Каждый запрос Inverse Design логируется в таблицу `design_targets` — это
история «цель → найденное покрытие», которая пригождается для будущего
развития ML-части проекта.

### 2. Нейросеть (суррогат)

Требует уже обученную суррогат-модель (папка с `model.joblib` +
`model_meta.json`, см. ниже — вкладка «ML-суррогат» в окне БД). Модель
заменяет честный TMM **только внутри поиска** — для быстрой оценки
кандидатов в NSGA-II/DE. Итоговый результат всегда честно пересчитывается
TMM перед показом и сохранением.

При **одновременном** включении этой вкладки и Inverse Design автоматически
активируется **seed-proposer** (см. ниже) — иначе суррогат просто подменяет
TMM внутри обычного NSGA-II.

Если полоса поиска выходит за пределы диапазона, на котором обучена
модель — в лог выводится явное предупреждение (модель вне своего диапазона
экстраполирует константой, предсказания там недостоверны; итог всё равно
будет честно проверен TMM).

## База данных

Файл `rc_absorber.db` (SQLite) заполняется автоматически после каждого
успешного прогона. Схема:

| Таблица | Содержимое |
|---|---|
| `materials` | Материалы (спектры εr/μr), дедуплицированы по содержимому |
| `optimisation_runs` | Метаданные каждого прогона |
| `coatings` | Найденные покрытия: состав, толщины, RC, полоса, чувствительность, опционально полная кривая RC(f) |
| `design_targets` | Запросы Inverse Design: цель → найденное покрытие |

По умолчанию сохраняются только валидные покрытия (RC ≤ порога) — управляется
чекбоксом в группе «База данных» главного окна. Там же — чекбокс сохранения
полных кривых RC(f) (нужны для последующего ML).

### Окно просмотра БД

Кнопка «База данных…» открывает окно с шестью вкладками:

1. **Материалы** — все накопленные материалы с алиасами (альтернативными
   именами одного и того же материала).
2. **Прогоны** — история всех запусков оптимизатора.
3. **Покрытия** — фильтры по прогону/материалу/валидности, график RC(f) при
   выборе строки (кривая восстанавливается прямо из БД — материалы
   подтягиваются по `material_id` независимо от исходной папки на диске).
4. **Экспорт датасета** — выбор конкретных прогонов и формирование
   обучающей выборки для ML (см. ниже), без командной строки.
5. **ML-суррогат** — обучение forward-суррогата на экспортированном
   датасете, с метриками качества (MAE, R²).
6. **История целей** — все запросы Inverse Design с результатами.

## ML-часть

### Экспорт датасета (`dataset_export.py`)

Превращает накопленные в БД покрытия в обучающую выборку:

```bash
python dataset_export.py --output ./ml_dataset --grid-points 201 \
    --runs 3,5,7        # опционально: конкретные прогоны, иначе вся БД
```

Спектры материалов и кривые RC(f) ресемплируются на единую каноническую
сетку частот (пересечение диапазонов задействованных материалов), чтобы
данные из разных прогонов были сопоставимы для модели.

Выход: `dataset_scalar.csv` (табличные признаки), `dataset_tensors.npz`
(тензоры для более сложных архитектур), `dataset_meta.json` (параметры
экспорта).

### Forward-суррогат (`ml_surrogate.py`)

`RandomForestRegressor` (scikit-learn), предсказывающий сразу всю кривую
RC(f) по составу покрытия (материалы + толщины слоёв, с паддингом до
максимального числа слоёв в датасете).

```bash
python ml_surrogate.py train --dataset ./ml_dataset --output ./surrogate_model
python ml_surrogate.py eval  --dataset ./ml_dataset --model ./surrogate_model
```

Обучение/оценка доступны и через GUI (вкладка «ML-суррогат» окна БД).

### Seed-proposer (`seed_proposer.py`)

Активируется автоматически при сочетании «Нейросеть (суррогат)» + Inverse
Design. Вместо честного DE+TMM для всех возможных последовательностей
материалов:

1. Перебирает (или сэмплирует, если комбинаторика велика) последовательности.
2. Суррогат быстро оценивает каждую — без единого TMM-вызова.
3. Top-K лучших уходят на честный DE+TMM.

Настройки (вкладка «Нейросеть (суррогат)»):
- **Top-K последовательностей на честный DE** (по умолчанию 15);
- **Пробных толщин на последовательность** (по умолчанию 8) — сколько
  случайных вариантов толщин суррогат перебирает при оценке одной
  последовательности.

Не требует новых данных сверх того, что уже накоплено для forward-суррогата
— переиспользует ту же модель.

## Дорожная карта проекта

| Этап | Статус |
|---|---|
| 0. Локальная БД (SQLite) | ✅ |
| 1. Экспорт датасета для ML | ✅ |
| 2. Forward-суррогат (обучение + ускорение поиска) | ✅ |
| 3. Inverse Design (целевая полоса + честный TMM) | ✅ |
| 3.5. История целей Inverse Design в окне БД | ✅ |
| 4. Seed-proposer (суррогат ранжирует последовательности) | ✅ |
| 5. Полноценная генеративная модель (настоящий inverse design) | ⬜ ждёт роста датасета |

Этап 5 сознательно не начат: генеративная модель (условная VAE/диффузия по
пространству материалов+толщин) требует существенно большего и разнообразного
датасета (разные диапазоны частот, наборы материалов, целевые пороги), чем
накоплено на данный момент. Дальнейшее движение по ML-ветке определяется
объёмом и разнообразием реальных данных, а не доработками кода.

## Технические заметки

- **Единица толщины** в БД — миллиметры; в физических вычислениях —
  метры (как исторически сложилось в `physics.py`).
- **Кеши `_trig_cache`/`_fitness_cache`** в `physics.py` ключуются по
  монотонному счётчику (`mat_arrays['_cache_id']`), а не по `id()` объекта —
  это защищает от коллизий кеша при переиспользовании памяти сборщиком
  мусора (актуально для коротко живущих объектов `mat_arrays`, например при
  построении графиков в окне БД).
- **Дедупликация материалов** — по хэшу содержимого спектра (freq+er+eim+
  mr+mim), а не по имени файла; альтернативные имена накапливаются в поле
  `aliases`.
- **Дедупликация покрытий** — по хэшу (материалы + квантованные толщины) в
  пределах одного прогона.
- Зависимости для основного функционала: `numpy`, `scipy`, `pandas`,
  `matplotlib`, `openpyxl`. Для ML-части дополнительно: `scikit-learn`,
  `joblib`.
